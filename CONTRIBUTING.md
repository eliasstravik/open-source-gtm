# Contributing

Thanks for contributing to `open-source-gtm`.

## Inclusion Criteria

- Every entry must have a public repo.
- Every entry must be plausibly useful for GTM work across sales, marketing, RevOps, customer success, growth, or GTM engineering.
- Every entry must have a verified license from the repo itself.
- Software sections require a verified OSI-approved license from the repo itself.
- Mixed-license, fair-code, and source-available software belongs in `Source-available`, with the license named.
- Unlicensed software is rejected.
- Unlicensed content repos are rejected.
- Archived or clearly unmaintained repos are rejected.

## Entry Format

Use one line per entry:

```md
- [Name](https://github.com/owner/repo) - Factual one-line description.
```

Use this note when it applies:

- A short license note for `Source-available` entries.

## Pull Request Checklist

- Confirm the repo URL is canonical and public.
- Verify the license from the repo itself, not a third-party directory.
- Put the entry in the narrowest useful section.
- Keep the description factual and plain.
- Avoid duplicates by name or URL.
- Exclude archived or clearly unmaintained repos.
- If you add software outside `Source-available`, verify it has an OSI-approved license.

## Removals And Fixes

Open a PR if an entry:

- moved or renamed repos
- changed license status
- no longer fits GTM use cases
- became archived, unmaintained, or unlicensed
- is duplicated or miscategorized
